# Analyzer 与编辑器能力

Rils Analyzer 通过 LSP 提供诊断、补全、Hover、定义跳转、引用查找、签名帮助、文档符号、语义
标记和类型内嵌提示。它复用 `rils_frontend` 的解析、类型检查、所有权检查和共享内建声明，避免
编辑器与编译器维护两套语言规则。

## 工作区分析

打开包含 `rils.toml` 的目录后，Analyzer 会加载项目脚本根目录下的所有模块，建立公开声明索引，
并为每个文件分配稳定的 `SourceId`。跨文件 `use`、`crate`、`self`、`super`、别名、分组导入和
通配导入都可以参与诊断与定义跳转。文件修改后工作区会重新分析，相关文件的诊断同步刷新。

公开声明的来源 Span 会保留目标文件身份，因此错误、定义和引用不会错误地指向入口文件。

公开函数、类型、trait 和模块可以经 `pub use` 重导出。显式名称、`as` 别名、分组、通配以及
多层重导出共用 frontend 导出图，保留原声明的 SourceId/DefId、签名、字段和所属模块。
例如 `origin::compute → relay::calculate → api::calculate` 的调用会跳转到 `origin` 中的定义；
从原定义查找引用也能找到中间导入与最终调用，结果按位置去重。公开重导出缺失、指向私有声明或
存在歧义时会报告导入位置，无法解析的循环不会无限遍历。

ProjectId 在同一会话的工作区重建中保持不变；模块查询用 `ProjectModuleId` 同时携带所属项目与
项目内 ModuleId。名称相同但目录不同的项目拥有不同身份。源索引只消费已注册 SourceId 的解析
快照，不以未知来源重新读取文件来猜测定义。这里不承诺 ModuleId/DefId 在任意源码结构变更后仍
保持原编号，也不承诺身份可以跨进程持久化。

工作区根没有 `rils.toml` 时，Analyzer 会尝试加载独立脚本并发现嵌套项目。根扫描遇到非法模块路径、
子项目配置损坏或目录读取失败时，会报告具体路径并继续发现其他项目；失败的 legacy 根本身不会被
部分加载。已加载项目的跨文件导航保持可用。临时语法错误会报告当前修订的诊断，同时保留最近一次
成功解析的语义快照用于编辑辅助。

## 标准库声明包

`rils_builtins/stdlib` 是标准库声明源码，构建时生成共享内建目录；发行包将同一份源码随 Analyzer
分发为 `rils_stdlib`。标准库作为可信语言依赖加载，其 prelude 单独索引为根声明。普通项目不能通过
修改 `rils.toml` 自行取得语言包解析权限。

Analyzer 按以下顺序查找包：

1. 显式 `RILS_SYSROOT` 下的 `packages/rils_stdlib`；配置无效时报告错误，不回退到其他包。
2. 相对 Analyzer 所在目录的 `../lib/rils/packages/rils_stdlib`（CLI 工具链布局）。
3. 相对 Analyzer 所在目录的 `../sysroot/packages/rils_stdlib`（VSIX 布局）。
4. 开发构建记录的仓库 `crates/rils_builtins/stdlib` 目录。

包缺失或加载失败会报告错误，LSP 服务继续运行。标准库源码中的占位函数体由编译器或运行时实现，
不执行普通函数体的名称、类型、控制流、所有权和格式检查；签名、符号和定义继续参与分析。
标准库文件并不整体免除诊断：语法错误、未知签名类型、重复声明仍正常发布。

只有保留可信来源且种类匹配的声明才能替换合成内建符号；此权限不适用于宿主符号，也不会通过
合并项目根传播给普通源码。

## 补全

补全来源包括：

- 共享内建目录中的模块、类型、构造函数、关联项和方法；
- Host Manifest 中声明的模块、类型、enum variant 与函数；
- 项目模块中的公开函数、类型、trait 和子模块；
- 任意可解析 receiver 的成员和 Iterator 等 trait 默认方法。

在模块路径后输入 `::`，或在成员表达式后输入 `.`，即可列出当前可访问的符号。未闭合的分组
`use` 也会提供候选项。

## 服务错误恢复

启动时逐个读取、解码、检查 ABI 并合并 Host Manifest；损坏、缺失、不兼容或冲突的片段会报告
具体路径并被跳过，其余有效片段仍可用。每个片段在临时副本上合并，失败不留下部分声明。
热重载采用事务更新：任一片段失败时保留上一次有效的完整宿主模型；修复后重新加载才替换它。
因此报错期间宿主补全可能仍展示旧模型，不代表新 Manifest 已生效。显式空列表可清除宿主模型。
目前宿主模型仍在服务内合并，尚不提供按项目独立的 Host Contract 隔离。

不可读或非 UTF-8 源码会报告文件路径并跳过，不影响其余已加载文件。错误的通知参数被报告并
忽略；请求参数错误返回 `InvalidParams`，未知请求返回 `MethodNotFound`。全文同步的空变更
列表不改变文档；不支持的增量变更不会被误用为全文替换。关闭后忽略在途通知，拒绝新请求，
收到 `exit` 后释放 IO 通道退出。

VS Code 在启动前扫描 Manifest 时也会跳过不可读子目录并警告，不阻断其他目录或语言客户端。
以上恢复针对可预期的输入和文件错误，不承诺恢复内存耗尽、栈溢出或编译器内部不变量失效；
初始化握手失败、损坏的协议流、客户端断开和输出通道失效仍会结束服务。

真实进程回归位于 `tools/rils-analyzer/tests/service_resilience.rs`，覆盖坏 Manifest、ABI 冲突、
失败重载、错误通知、缺失 sysroot、不可读源码和关闭握手。整仓库冒烟测试单独运行：

```text
cargo test -p rils_analyzer --test service_resilience repository_workspace -- --ignored
```
