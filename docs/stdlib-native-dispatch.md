# 标准库原生调用迁移

## 目标

`#[decl_rils(...)]` 内的导出声明是标准库 API 及其 Rust 实现的来源。原生方法由规范符号路径定位，解释器和 VM 共用执行入口。

## 调用身份与执行

编译期用已解析的声明身份表示调用目标，保留所属模块、类型或 trait、方法和签名。这个身份与源码中采用的简写、`use` 别名无关。生成器同时从导出声明生成类型检查元信息和运行时桥接函数；桥接函数负责检查实参、按 receiver 模式读取或移动值、转换代理类型、调用 Rust 方法体，再转换返回值和错误。解释器与 VM 使用同一组桥接函数。

## 原生值存储

运行时数据的目标存储边界是 Native（已注册的具体 Rust 布局）、Dynamic（由具体 Rils 类型递归组合的布局）和 Host（宿主提供的不透明对象）。引用、调用目标、模块和类型声明属于执行控制对象，不作为第四种数据负载。执行层已为组合存储中的引用与函数值登记原生叶子布局，bytes 保存词法租约或调用目标句柄，消费时恢复同一执行身份；独立函数值的完整描述仍待统一。当前 `RilsValue` 已是不透明的宿主结果句柄，内部旧 `Value` 枚举与兼容入口仍在逐步收缩。执行层的 `StoredDataRef` 已将三种数据负载与其他执行值区分，`TypedStorageContext` 使用执行处可见的 struct/enum/HostType 声明，在类型化局部绑定、记录字段、tuple enum 字段及可从实参推断具体类型的函数参数处统一解析布局并移动所有权。缺少原生布局的合法运行时值暂保留旧表示；布局已解析但负载不匹配时返回错误。`NativeOwnedContext` 将宿主声明与 Copy 策略自动传入参数、返回、表达式、字段、空集合及 Box/Rc/Cell/RefCell 构造；VM 在启动时合并模块与宿主声明，嵌套回调和格式化调用沿用上下文。Host enum 从共享契约生成完整变体，包括 raw flags 分支。非 Copy 宿主叶子的兼容借用读取保留同一对象句柄，不将它变成 Copy；基类字段保存派生宿主对象的实际身份。

类型化 `Option<Item>`、`Result<Item, E>` 和用户 enum 分支现可在解释器与 VM 中按声明组合原生布局。消费式 `unwrap` 从负载移出子值，借用读取可使用 `RilsValue::with_native_view` 沿字段路径访问，不必先还原为拥有型 `Value`。字节码编译器将参数声明降为函数入口处的类型化局部初始化；转换上下文可从实参推断 `Option<T>`、`Result<T, E>` 中的具体 `T`，沿用现有字节码指令和 v8 磁盘格式。无法从实参推断类型的泛型实例、函数直接返回值、通用引用及方法适配器仍可能使用旧转换桥，因此不能据此删除旧枚举。

组合布局的格式化会沿借用视图递归读取记录字段和 enum 分支，非 Clone 的用户值也能保持原有 Display/Debug 输出。enum 分支名属于布局描述与兼容性检查的一部分，避免同类型但标签顺序不同的负载互认。

`rils_native` 现提供布局工厂与元素借用读取的注册协议，注册表只保存函数指针。`rils_stdlib` 在 Vec 与 string 的定义文件旁提供相应注册项，`rils_stdlib_macros::native_registry!` 扫描这些定义文件并生成汇集表；`rils_execution` 从该表解析 Vec 布局并判断元素读取能力。其他标准库类型的布局与运行时转换仍有执行层过渡实现，后续按同一协议迁移。注册项内容仍需在定义处显式声明，自动汇集不推断类型的借用语义。

类型化空 `Vec<string>` 现与 Copy 元素 Vec 共用原生序列和索引租约。字符串元素在 `&` / `&mut` 引用、借用迭代和 `contains()` 读取时会经现有 `Value` 边界克隆文本，替换元素则按索引写回原序列；结构性修改先检查活动租约。直接按索引移出非 Copy 字符串继续报错。这仍是过渡适配，后续通用非 Copy 引用需要让调用入口在短暂借用下直接访问负载。

动态原生序列的负载现在把元素与引用账本一起保存。Rils 元素引用仅持有容器句柄、索引和自动释放的租约；读写时才短暂借用负载，因此多个指向同一元素的 Rils `&mut` 不会形成重叠的 Rust `&mut`。租约存活时禁止会改变索引或销毁元素的结构性操作；借用迭代器的租约还禁止元素写入。具体元素布局为 Copy 或 `string` 的类型化空 `Vec<T>` 已使用这套负载，解释器和 VM 的索引、方法、借用与拥有型迭代均接入该引用机制；其他非 Copy 元素及无具体类型见证的构造仍使用旧表示。

独立的 `rils_value` crate 提供 `NativeType<V>` 与 `NativeObject<V>`，只依赖共享类型模型，不依赖解释器或 VM。执行层的 `Value::Native` 接入这组泛型存储。登记为 Copy 且尺寸不超过 32 字节、对齐不超过 16 字节的 Rust 值直接存入对象；其他值使用共享堆存储。布局擦除、按已登记 Copy 保证复制以及析构集中在 `storage.rs`，其余代码只通过带 `TypeId` 检查的类型化入口访问值。

类型通过 `register_method` 自行注册任意操作；`NativeCallContext` 提供 receiver、参数和同类型对象构造入口，存储 crate 不限定 Clone、Equal、Display、Next 等方法。当前执行层用少量适配器把已注册操作接到 `Value` 的克隆、比较、显示和迭代接口，`Range<T>` 逐项注册所需操作。后续应从标准库导出声明生成这批注册，而不是继续手写描述表。内联 Copy handle 采用值语义；需要修改它的 `&mut self` 方法必须由 place 层写回。共享存储的可变访问使用短暂的动态借用，重入时返回错误，避免把多条 Rils `&mut` 引用同时转成 Rust `&mut T`。存储槽继续决定何时允许 move，词法引用仍指向 Rils place。

`Range<T>` 已通过此路径保存为 `rils_stdlib::Range<T>`，范围字面量和 `next()` 在解释器与 VM 中使用相同的原生迭代器实现。运行时类型名保留泛型参数，例如 `Range<i32>`。整数边界到 Rust 类型的转换仍在范围构造适配器内；`Range` 的方法身份仍由标准库导出声明提供。字节码只编码构造指令和类型，不保存原生负载的指针或 Rust 布局。

当前实际接入范围是 `Range<T>`、全部标准库整数宽度、`f32`、`f64`、`char`、`string`，以及子类型可由标准库布局递归解析的 `Option<T>`。所有整数宽度的字面量、默认值、算术结果及字节码常量使用内联的 `Number<T>` 负载；整数方法的原生描述符由标准库导出声明生成，注册函数通过 `NativeCallContext` 类型化读取 receiver、检查实参并直接调用 Rust 方法。`i8`、`i32` 运算直接读取原生负载；其他整数宽度的旧数值指令仍经 `numeric::scalars` 的过渡转换执行，结果重新封装为原生负载。集合长度、索引和计数入口通过 `Value::as_usize()` 读取原生值。Rust 宿主通过 `Value::from_i16()` / `Value::as_i16()` 等对应宽度的方法构造和读取整数；旧数值变体仍可作为输入。C ABI 保持既有整数标签。`Option<T>` 的子布局现在复用通用布局解析与所有权编解码，支持布尔、字符、数值、字符串及可解析的嵌套标准库容器；共享前端把函数实参、赋值、字段和嵌套表达式的预期类型传给 `None`，解释器与 VM 据此使用相同布局。用户定义 `T` 已可在类型化局部绑定、记录字段、tuple enum 字段和具体类型函数参数中使用可见声明解析布局；嵌套引用报告与其他执行路径仍需继续迁移。

带具体标准库元素布局的 `VecDeque<T>` 和 `BinaryHeap<T>` 在类型化局部绑定中现使用声明生成的动态序列布局。解释器与 VM 都在初始化时取得具体 `T`；VM 的 `InitLocal` 指令携带可选的声明类型，但不在 VM 内重新执行通用类型检查。序列元素以各自布局的原生负载保存，嵌套容器可以按所有权移入。`VecDeque` 的入队、出队、长度查询与清空，以及 `BinaryHeap` 的插入、弹出、堆顶克隆、长度查询与清空现直接访问动态负载。`BinaryHeap` 的比较通过具体元素布局提取有序键；Copy 和字符串元素的端点克隆也直接读取负载，其他端点克隆与整个容器克隆仍使用消耗式转换桥。当前动态序列以 `Vec<DynamicValue>` 保存元素，`VecDeque` 的前端插入与弹出还不是常数时间。无类型见证或元素布局无法解析时仍使用旧 `Value` 容器，类型化局部绑定已把可见用户定义声明传入布局解析器，其他序列构造入口仍需接入同一上下文。

`f32`、`f64` 的字面量、默认值、运算与标准库方法结果使用内联的 `Number<T>` 原生负载；旧 `Value::F32` / `Value::F64` 仍可作为 Rust 宿主输入。宿主应通过 `Value::from_f32()` / `Value::from_f64()` 构造，通过 `as_f32()` / `as_f64()` 读取运行结果。浮点 C ABI 标签及字节码编码保持不变。

`DynamicLayout` 已为上述泛型方向提供可组合的布局：`Option<T>` 按子类型的尺寸和对齐计算负载位置，并通过子类型的析构操作处理嵌套值；`None` 只保存标记字节。`DynamicObject<V>` 让 Copy 布局使用内联句柄，其他布局使用共享存储；`DynamicType<V>` 可按任意名称注册操作，并在调用时校验 receiver 的布局身份。整数族、浮点数、`string` 与 `Option<T>` 的布局工厂已由 `decl_rils_layout` 从标准库声明生成；整数和字符串方法返回的 `Option<T>` 已沿用动态构造入口。`Option<T>` 的可执行方法注册仍需扩展过程宏，目前由过渡适配器读取其原生负载。

动态布局现可组合用户结构体字段：声明顺序决定字段索引，布局计算字段对齐和偏移，布局描述保存名称到索引的映射。字段活跃标记位于值的存储中，嵌入其他结构或 `Option<T>` 后仍能正确处理单字段 move、回填与析构。执行层的 `RecordLayoutResolver` 从现有 `StructType` 声明与具体泛型实参递归解析布局并缓存描述符；没有已注册原生布局的字段明确报错。已解析的本模块用户结构体字段在字节码中保存类型与字段索引，并通过 verifier 校验；解释器按字段声明缓存名称到索引的映射。两端的用户实例直接使用原生 bytes，字段 place 与词法引用沿检查过的布局路径读取、移动和写回。旧 `Value::Struct` / `Value::Enum`、`StructInstance` / `EnumInstance` / `EnumPayload` / `StructFields` 及 `compose_nominal` 已删除；Rust 构造入口使用 `TypedStorageContext::construct_record/construct_tuple_variant/construct_unit_variant`，读取使用 `RilsValue` 或 `NativeInstancePlace`。`NativeRecordCodec` 移入已有原生值时保留布局所涉及的声明身份，拒绝同名但身份冲突的声明，解码后继续保留具体泛型与显式 Copy 策略。磁盘字节码不直接写入平台相关的字节偏移。

`Option<T>` 的构造入口消耗 `Option<Value>`，若子类型尚无原生布局则把原值归还给旧表示路径。解释器的 `Some` 与 VM 的构造指令使用拥有的实参；唯一持有的原生 `string` 通过 `NativeObject::into_rust` 移出后进入动态子布局，避免文本克隆。共享原生句柄在借用型运行时入口下需显式生成独立负载；`Option<T>` 的通用读取桥会暂时移出、解码并恢复负载，因此非 Copy 子值的读取仍可能产生 Clone，后续应改为针对布局的借用访问。

包含 Rils 值的原生容器通过 `NativeChildren` 向 place 层报告嵌套引用、活动引用和部分 move；负载正在被可变访问时，这些检查保守地视为存在风险。继续迁移容器前，需要从标准库声明生成类型描述及操作绑定，并为每个容器实现该报告接口。动态 Rils 类型无法直接实例化任意 `Vec<T>` 的 Rust 单态化版本，仍需独立的运行时布局与元素操作表。

磁盘字节码中的原生导入项保存规范符号路径与签名，调用指令只引用导入项索引。加载时验证索引、签名及可用实现；当前 VM 执行时按导入项路径调用生成桥接，后续将其链接为进程内调用槽位，避免每次按字符串查找。进程内槽位与 Rust 函数指针均不写入磁盘。脚本函数仍保留直接调用指令；作为值传递的原生函数尚待迁移。

真正属于语言执行语义的操作继续使用专门的 MIR/VM 操作，例如所有权、词法引用、控制流和基础数值运算。数值类型上的普通关联函数与方法则应逐步转为原生调用。宿主导入及其 ABI 身份独立于标准库原生符号。

具备具体类型的 `Result<T, E>` 在两个分支的布局均可读取时，类型化绑定会使用 `DynamicLayout::variant` 保存带标签负载。基础标量、`string` 及 Copy 的嵌套布局已接入；解释器和 VM 的方法、模式匹配、`?` 与格式化入口可读取新旧表示。Rust 宿主通过 `Value::as_result()` 读取。非 Copy 复合分支和用户定义子类型尚未进入这条运行时路径。

## 当前调用链与后续工作

宿主 enum 的声明保留完整 Manifest 契约身份，包括整数宽度、discriminant、flags 和变体名称。
同一契约重新构造的值可绑定到当前执行声明；方法和 trait 表保持执行上下文的所有权。
VM 校验字节码里的宿主 enum 形状后链接已安装契约。不同契约，以及同名但身份不同的脚本声明，不能混用。
直接构造 `EnumType` 的 Rust 代码需要填写 `host_definition`：脚本声明用 `None`，宿主 enum 使用共享声明工厂。

标准库导出声明生成规范符号路径、类型检查元信息和原生桥接入口。前端解析数值方法及导出方法后，HIR/MIR 生成符号原生导入；解释器和 VM 从同一份声明定位执行入口。Prelude 中的转发函数使用 `#[native_method(core::...)]` 声明目标。

旧 `BuiltinId`、ID 表、`#[rils_legacy_id]`、`CallRuntime` 和 `CallIntrinsic` 均已移除。包含旧数字调用的实验性 v8 字节码必须从源码重新编译。复杂的泛型值、借用与回调仍有执行层适配器，后续应从导出声明继续生成这些转换，并在加载时把原生导入链接为进程内调用槽位。

迁移期间每一步都需要验证解释器与 VM 的执行结果一致，并覆盖字节码读写、无效符号和签名不匹配的失败路径。

`string` 的字面量、标准库返回值和宿主边界使用 `rils_stdlib::String` 的原生负载；Rust 宿主通过 `Value::from_string` 构造、`Value::as_string` 读取。旧 `Value::String` 变体已移除。过程宏从字符串的导出声明生成类型描述和原生方法操作表；原生 receiver 直接借用包装对象调用 Rust 方法，传入拥有型字符串参数时才需要复制文本。

## 函数值与回调的后续设计

Rils 已有精确的 `fn(A, B) -> R` 类型和携带捕获环境的函数值。标准库已导出 `FnOnce`、`FnMut` 和 `Fn`，都以 `<Args, Output>` 表示签名，参数打包为 tuple。解释器同时检查精确签名和捕获行为；保守分类不会把可能消费捕获值的闭包视为可重复调用。字节码编译器当前明确拒绝这组三种 bound，直到共享前端能够验证它们；未知签名的兼容类型 `function` 不能无条件获得精确的调用 trait 实现。

Option/Result 的 `map`、`map_err`、`and_then`、`or_else` 及 Option 的 `filter` 已从导出签名生成回调原生符号。其 `#[export_rils]` 方法直接使用带 `FnOnce` 约束、返回普通值的 Rust 实现；声明生成器把回调约束转成 Rils 精确 `fn(...) -> ...` 类型，并生成隐藏的可失败实现，在直接回调调用点传播错误。桥接器把函数值交给解释器或 VM 的调用入口；`filter` 的谓词接收指向当前值的词法共享引用。回调可读取捕获环境，错误以带类型的结果保留原始源码位置；VM 的嵌套调用沿用调用深度和步数预算。带 `Fn`/`FnMut`/`FnOnce` 泛型回调约束的 `#[rils_fn]` 自由函数也从唯一的 Rust 实现推导声明和可失败桥接；多个回调、任意参数位置与任意回调参数个数共用这一入口，泛型值以运行时 `Value` 传递，标量与 unit 使用显式转换。当前只改写直接回调调用；`return`、嵌套闭包和表达式宏会被明确拒绝。Rils 侧仍以精确 `fn` 类型表示导出参数，字节码编译器尚不能验证 `Fn*` 泛型 bound；引用、容器和其他复杂 Rust 类型的通用转换也尚未覆盖。

Vec 的部分方法已使用可写 receiver 代理：桥接器把运行时元素槽位临时移入 `rils_stdlib::Vec<FieldSlot>`，调用导出的 Rust 方法后由代理的析构逻辑归还槽位。整个过程不逐元素复制，保留元素引用计数和类型标注；结构性修改先执行已有的引用与迭代器检查。`Vec::into_iter` 消费槽位并转换为运行时拥有型迭代器，保留槽位队列供 `next()` 逐项移出，转换时不逐元素复制；移动前检查活动引用和部分移动状态。数组与 Vec 的 `iter()` 和 `contains()` 现通过原生符号桥接，借用迭代器保留词法来源和结构性修改保护。Copy 元素的原生 Vec 使用声明中的符号查找方法，再由执行层对原生序列负载执行；`extend` 可接收原生或旧表示的 Vec。非 Copy 元素仍走原有代理。`T`、`Option<T>` 等泛型返回值仍需要逐步完善运行时类型见证和所有权转换；尚未移除的旧 ID 在字节码兼容路径退出前继续保留。
