# 标准库原生调用迁移

## 目标

`#[decl_rils(...)]` 内的导出声明是标准库 API 及其 Rust 实现的来源。普通原生方法不再需要在 `builtin_ids.toml` 中分配稳定编号，也不应在解释器和 VM 内分别维护方法分发表。

## 调用身份与执行

编译期用已解析的声明身份表示调用目标，保留所属模块、类型或 trait、方法和签名。这个身份与源码中采用的简写、`use` 别名无关。生成器同时从导出声明生成类型检查元信息和运行时桥接函数；桥接函数负责检查实参、按 receiver 模式读取或移动值、转换代理类型、调用 Rust 方法体，再转换返回值和错误。解释器与 VM 使用同一组桥接函数。

磁盘字节码中的原生导入项保存规范符号路径与签名，调用指令只引用导入项索引。加载时验证索引、签名及可用实现；当前 VM 执行时按导入项路径调用生成桥接，后续将其链接为进程内调用槽位，避免每次按字符串查找。进程内槽位与 Rust 函数指针均不写入磁盘。脚本函数仍保留直接调用指令；作为值传递的原生函数尚待迁移。

真正属于语言执行语义的操作继续使用专门的 MIR/VM 操作，例如所有权、词法引用、控制流和基础数值运算。数值类型上的普通关联函数与方法则应逐步转为原生调用。宿主导入及其 ABI 身份独立于标准库原生符号。

## 迁移顺序

1. 由导出声明生成按规范符号路径调用的桥接入口，让旧 `BuiltinId` 调用作为过渡适配。当前 Option/Result 已进入此阶段，未生成桥接的方法仍由旧运行时处理。
2. 扩展桥接生成器，覆盖参数、泛型擦除、引用、可变 receiver、返回值、回调和错误转换，逐一迁移旧运行时的方法实现。
3. 前端、HIR、MIR 使用声明身份表示已迁移的原生调用；实验性 `.rilbc` v8 已增加原生导入项和 `CallNative` 指令。String 方法及 Option/Result 的六个直接原生方法已移除旧 ID，其他未迁移 API 暂时保留旧指令。后续将原生导入链接成进程内调用槽位。
   Prelude 中需要转发到原生方法的全局函数使用 `#[native_method(core::...)]` 声明目标；解释器和字节码编译器均按函数路径查询这份声明，再使用其原生符号，不另列目标路径分发表。
4. 所有依赖迁移完成后，删除旧的 `CallRuntime` / `CallIntrinsic` 编码、`BuiltinId`、ID 表及不再需要的分发表；届时固定 v8 的最终布局，并在变更记录中说明重新编译要求。

迁移期间每一步都需要验证解释器与 VM 的执行结果一致，并覆盖字节码读写、无效符号和签名不匹配的失败路径。旧格式仍被当前版本接受时，不得删除其编号验证逻辑。
