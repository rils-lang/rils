# 标准库原生调用迁移

## 目标

`#[decl_rils(...)]` 内的导出声明是标准库 API 及其 Rust 实现的来源。普通原生方法不再需要在 `builtin_ids.toml` 中分配稳定编号，也不应在解释器和 VM 内分别维护方法分发表。

## 调用身份与执行

编译期用已解析的声明身份表示调用目标，保留所属模块、类型或 trait、方法和签名。这个身份与源码中采用的简写、`use` 别名无关。生成器同时从导出声明生成类型检查元信息和运行时桥接函数；桥接函数负责检查实参、按 receiver 模式读取或移动值、转换代理类型、调用 Rust 方法体，再转换返回值和错误。解释器与 VM 使用同一组桥接函数。

## 原生值存储

独立的 `rils_value` crate 提供 `NativeType<V>` 与 `NativeObject<V>`，只依赖共享类型模型，不依赖解释器或 VM。执行层的 `Value::Native` 接入这组泛型存储。登记为 Copy 且尺寸不超过 32 字节、对齐不超过 16 字节的 Rust 值直接存入对象；其他值使用共享堆存储。布局擦除、按已登记 Copy 保证复制以及析构集中在 `storage.rs`，其余代码只通过带 `TypeId` 检查的类型化入口访问值。

类型通过 `register_method` 自行注册任意操作；`NativeCallContext` 提供 receiver、参数和同类型对象构造入口，存储 crate 不限定 Clone、Equal、Display、Next 等方法。当前执行层用少量适配器把已注册操作接到 `Value` 的克隆、比较、显示和迭代接口，`Range<T>` 逐项注册所需操作。后续应从标准库导出声明生成这批注册，而不是继续手写描述表。内联 Copy handle 采用值语义；需要修改它的 `&mut self` 方法必须由 place 层写回。共享存储的可变访问使用短暂的动态借用，重入时返回错误，避免把多条 Rils `&mut` 引用同时转成 Rust `&mut T`。存储槽继续决定何时允许 move，词法引用仍指向 Rils place。

`Range<T>` 已通过此路径保存为 `rils_stdlib::Range<T>`，范围字面量和 `next()` 在解释器与 VM 中使用相同的原生迭代器实现。运行时类型名保留泛型参数，例如 `Range<i32>`。整数边界到 Rust 类型的转换仍在范围构造适配器内；`Range` 的方法身份仍由标准库导出声明提供。字节码只编码构造指令和类型，不保存原生负载的指针或 Rust 布局。

当前实际接入范围是 `Range<T>`、`i8`、`i32` 和 `usize`。这三种整数的字面量、默认值、算术结果及字节码常量使用内联的 `Number<T>` 负载；整数方法的原生描述符由标准库导出声明生成，注册函数通过 `NativeCallContext` 类型化读取 receiver、检查实参并直接调用 Rust 方法。旧数值指令仍通过集中在 `numeric::scalars` 的过渡转换使用原有逻辑；集合长度、索引和计数入口通过 `Value::as_usize()` 读取原生值。Rust 宿主可用 `Value::as_i8()` / `Value::as_i32()` / `Value::as_usize()` 读取新旧两种表示；C ABI 保持既有整数标签。`string` 和 `Option<T>` 仍使用原有 `Value` 分支；对应 Rust 负载的布局测试只证明存储能力。泛型 `Option<T>` 还需要运行时类型见证及嵌套值的布局、析构和引用报告，不能仅用有限的 Rust 单态化实例代替任意 Rils `T`。

`DynamicLayout` 已为上述泛型方向提供可组合的布局：`Option<T>` 按子类型的尺寸和对齐计算负载位置，并通过子类型的析构操作处理嵌套值；`None` 只保存内联标记。`DynamicType<V>` 可按任意名称注册操作，并在调用时校验 receiver 的布局身份。整数族、`string` 与 `Option<T>` 的布局工厂已由 `decl_rils_layout` 从标准库声明生成；可执行方法注册仍需扩展同一过程宏，之后才能迁移实际运行时值。

包含 Rils 值的原生容器通过 `NativeChildren` 向 place 层报告嵌套引用、活动引用和部分 move；负载正在被可变访问时，这些检查保守地视为存在风险。继续迁移容器前，需要从标准库声明生成类型描述及操作绑定，并为每个容器实现该报告接口。动态 Rils 类型无法直接实例化任意 `Vec<T>` 的 Rust 单态化版本，仍需独立的运行时布局与元素操作表。

磁盘字节码中的原生导入项保存规范符号路径与签名，调用指令只引用导入项索引。加载时验证索引、签名及可用实现；当前 VM 执行时按导入项路径调用生成桥接，后续将其链接为进程内调用槽位，避免每次按字符串查找。进程内槽位与 Rust 函数指针均不写入磁盘。脚本函数仍保留直接调用指令；作为值传递的原生函数尚待迁移。

真正属于语言执行语义的操作继续使用专门的 MIR/VM 操作，例如所有权、词法引用、控制流和基础数值运算。数值类型上的普通关联函数与方法则应逐步转为原生调用。宿主导入及其 ABI 身份独立于标准库原生符号。

## 迁移顺序

1. 由导出声明生成按规范符号路径调用的桥接入口，让旧 `BuiltinId` 调用作为过渡适配。当前 Option/Result 已进入此阶段，未生成桥接的方法仍由旧运行时处理。
2. 扩展桥接生成器，覆盖参数、泛型擦除、引用、可变 receiver、返回值、回调和错误转换，逐一迁移旧运行时的方法实现。
3. 前端、HIR、MIR 使用声明身份表示已迁移的原生调用；实验性 `.rilbc` v8 已增加原生导入项和 `CallNative` 指令。String 方法、Option/Result 的六个状态/转换方法和八个回调方法、Vec 的 `len`、`is_empty`、`iter`、`contains`、`push`、`pop`、`clear`、`truncate`、`insert`、`remove`、`swap_remove`、`into_iter`，以及 `Range::next` 使用原生符号。已迁移的原生方法不再自动登记数字 ID；Vec 的其他旧编号暂时保留在兼容表中读取旧字节码。旧 Sequence 的六个 ID 已删除，引用它们的实验性 v8 字节码必须重编。其他未迁移 API 暂时保留旧指令。后续将原生导入链接成进程内调用槽位。
   Prelude 中需要转发到原生方法的全局函数使用 `#[native_method(core::...)]` 声明目标；解释器和字节码编译器均按函数路径查询这份声明，再使用其原生符号，不另列目标路径分发表。
   `#[export_rils]` 固有方法及 `#[rils_impl]` 导出的方法默认生成原生符号，不再需要 `#[rils_native]`。Vec 的共享标量查询按签名生成 Rust 调用；结构修改和拥有型迭代把生成的调用交给 receiver 适配器，以保留引用与移动检查。借用迭代等复杂转换仍需专门的适配器。
   尚未迁移的方法必须显式绑定 `#[rils_legacy_id(...)]` 或 `#[rils_import(...)]`；不再按方法路径自动推断旧 ID。缺少原生转换或 receiver 适配器时，桥接生成在编译期报错。声明目录与执行入口通过覆盖测试保持一致。
4. 所有依赖迁移完成后，删除旧的 `CallRuntime` / `CallIntrinsic` 编码、`BuiltinId`、ID 表及不再需要的分发表；届时固定 v8 的最终布局，并在变更记录中说明重新编译要求。

迁移期间每一步都需要验证解释器与 VM 的执行结果一致，并覆盖字节码读写、无效符号和签名不匹配的失败路径。旧格式仍被当前版本接受时，不得删除其编号验证逻辑。

## 函数值与回调的后续设计

Rils 已有精确的 `fn(A, B) -> R` 类型和携带捕获环境的函数值。标准库已导出 `FnOnce`、`FnMut` 和 `Fn`，都以 `<Args, Output>` 表示签名，参数打包为 tuple。解释器同时检查精确签名和捕获行为；保守分类不会把可能消费捕获值的闭包视为可重复调用。字节码编译器当前明确拒绝这组三种 bound，直到共享前端能够验证它们；未知签名的兼容类型 `function` 不能无条件获得精确的调用 trait 实现。

Option/Result 的 `map`、`map_err`、`and_then`、`or_else` 及 Option 的 `filter` 已从导出签名生成回调原生符号。其 `#[export_rils]` 方法直接使用带 `FnOnce` 约束、返回普通值的 Rust 实现；声明生成器把回调约束转成 Rils 精确 `fn(...) -> ...` 类型，并生成隐藏的可失败实现，在直接回调调用点传播错误。桥接器把函数值交给解释器或 VM 的调用入口；`filter` 的谓词接收指向当前值的词法共享引用。回调可读取捕获环境，错误以带类型的结果保留原始源码位置；VM 的嵌套调用沿用调用深度和步数预算。带 `Fn`/`FnMut`/`FnOnce` 泛型回调约束的 `#[rils_fn]` 自由函数也从唯一的 Rust 实现推导声明和可失败桥接；多个回调、任意参数位置与任意回调参数个数共用这一入口，泛型值以运行时 `Value` 传递，标量与 unit 使用显式转换。当前只改写直接回调调用；`return`、嵌套闭包和表达式宏会被明确拒绝。Rils 侧仍以精确 `fn` 类型表示导出参数，字节码编译器尚不能验证 `Fn*` 泛型 bound；引用、容器和其他复杂 Rust 类型的通用转换也尚未覆盖。

Vec 的部分方法已使用可写 receiver 代理：桥接器把运行时元素槽位临时移入 `rils_stdlib::Vec<FieldSlot>`，调用导出的 Rust 方法后由代理的析构逻辑归还槽位。整个过程不逐元素复制，保留元素引用计数和类型标注；结构性修改先执行已有的引用与迭代器检查。`Vec::into_iter` 消费槽位并转换为运行时拥有型迭代器，保留槽位队列供 `next()` 逐项移出，转换时不逐元素复制；移动前检查活动引用和部分移动状态。数组与 Vec 的 `iter()` 和 `contains()` 现通过原生符号桥接，借用迭代器保留词法来源和结构性修改保护；`extend` 和其他容器尚未接入代理。`T`、`Option<T>` 等泛型返回值仍需要逐步完善运行时类型见证和所有权转换；尚未移除的旧 ID 在字节码兼容路径退出前继续保留。
